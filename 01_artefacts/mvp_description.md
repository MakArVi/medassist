# Описание проекта для создания MVP

Дата: 2026-10-04. Основа: `00_input/`, `target_audience.md`, `market_analysis.md`, `competitor_analysis.md`.
Пункты, помеченные ⚠️, — допущения, их нужно подтвердить.

## 1. Суть проекта

**Мы снижаем рутинную документационную нагрузку на врачей при помощи ИИ-ассистента, который слушает приём, сам заполняет протокол, а врач только проверяет и подписывает.**

- **Юзеры:** врачи частных клиник.
- **Клиент (ЦА):** частные клиники среднего сегмента.
- **ЛПР:** руководители сети, главные врачи.
- **Модель:** B2B, подписка за врача в месяц.

## 2. Проблема и ценность

- На 1 час приёма — почти 2 часа документации, около 45% врачей с признаками выгорания.
- Независимые исследования ИИ-скрайбов: экономия 16–27 минут на 8 часов приёма, выгорание снижается с 51.9% до 38.8% за 30 дней.
- Для клиники: больше приёмов на врача, меньше текучки, единый стандарт документов. Расчёт окупаемости: см. `market_analysis.md` (1.6–2.7× при цене 5 000 ₽/врач/мес ⚠️).

## 3. Конкурентная ситуация и гипотеза отстройки

Уже есть Яндекс Мед, Клиентикс, Ленивый доктор (см. `competitor_analysis.md`). Одной функции «голос → протокол» мало.

**Гипотеза отстройки для MVP ⚠️:** протокол, подстроенный под конкретную специальность и шаблоны клиники, плюс пилот «под ключ» с измеримым эффектом (минуты на врача, число приёмов).

## 4. Цель MVP и критерии успеха

**Цель:** проверить, что врач частной клиники готов ежедневно пользоваться ассистентом, а ЛПР готов платить.

| Метрика | Целевое значение ⚠️ |
|---|---|
| Время на документацию на приём | −40% и больше |
| Доля приёмов, где врач использует ассистент | ≥ 60% через 2 недели |
| Доля протоколов, принятых врачом с правками до 20% текста | ≥ 70% |
| NPS врачей | ≥ 30 |
| Клиник в пилоте | 2–3, 10–20 врачей |
| Согласие ЛПР на платную подписку после пилота | минимум 1 из 3 клиник |

## 5. Объём MVP

### Входит (must have)
1. **Запись приёма:** веб-страница или мобильное приложение, кнопка «начать приём» с согласием пациента на запись.
2. **Распознавание речи** с разделением реплик врача и пациента.
3. **Генерация черновика протокола** с помощью LLM: жалобы, анамнез, диагноз, назначения, рекомендации.
4. **Шаблоны по специальностям:** 2–3 специальности для пилота (например, терапевт, невролог, педиатр ⚠️).
5. **Редактор протокола:** врач правит текст и подтверждает.
6. **Экспорт:** копирование в МИС (на первом этапе — копировать / скачать; интеграция — позже).
7. **Кабинет клиники:** список врачей, простая статистика использования.
8. **Безопасность:** хранение данных в РФ, обезличивание, удаление аудио по умолчанию, соответствие 152-ФЗ.

### Не входит (после MVP)
- Глубокая интеграция с МИС (API), заказ анализов и назначений.
- Подсказки по диагнозу и лечению (клинические решения; регуляторные риски медизделия).
- Мобильные приложения под все платформы, офлайн-режим.
- Биллинг и кодирование.

## 6. Пользовательский сценарий

1. Врач открывает приём в приложении, пациент соглашается на запись.
2. Ассистент в фоне записывает и расшифровывает разговор.
3. После приёма за ~30 секунд формируется черновик протокола по шаблону специальности.
4. Врач проверяет, правит, подтверждает и копирует в МИС.
5. Руководитель клиники видит в кабинете: сколько приёмов, сколько минут сэкономлено.

## 7. Техническая схема (черновик)

| Блок | Решение ⚠️ |
|---|---|
| Клиент | веб-приложение (PWA) для ПК и смартфона |
| Распознавание речи | российское или локально развёрнутое ASR (SpeechKit, GigaAM, Whisper) с диаризацией |
| Генерация протокола | LLM (YandexGPT / GigaChat / развёрнутая open-source модель) + шаблоны и промпты по специальностям |
| Хранилище | сервер в РФ, шифрование, роль-доступ, журнал действий |
| Админка | кабинет клиники и аналитика использования |

Ключевой выбор: облако или модель в контуре клиники — зависит от требований пилотных клиник к данным.

## 8. Риски и меры

| Риск | Мера |
|---|---|
| Недоверие врачей, саботаж | обучение, быстрый выигрыш в первый день, врач-«чемпион» в клинике |
| Ошибки ИИ в протоколе | обязательная проверка врачом, подсветка непроверенных полей |
| Персональные данные (152-ФЗ), запись разговора | согласие пациента, обезличивание, хранение в РФ |
| Сильные конкуренты (Яндекс) | узкая специализация, личный онбординг, пилот с цифрами |
| Нет интеграции с МИС | на MVP копирование текста; интеграция по запросу пилотных клиник |
| Качество распознавания (медтермины, шум) | словарь терминов, тест на реальных записях в пилоте |

## 9. План на MVP ⚠️

| Этап | Срок | Результат |
|---|---|---|
| 0. Интервью с 5–10 главврачами и врачами | 2 недели | подтверждённые боль, цена, требования к данным |
| 1. Прототип: запись → расшифровка → протокол (1 специальность) | 3–4 недели | демо для интервью |
| 2. MVP: шаблоны, редактор, кабинет, безопасность | 4–6 недель | версия для пилота |
| 3. Пилот в 2–3 клиниках | 4 недели | метрики по таблице раздела 4 |
| 4. Итог: решение о развитии, цена, интеграции | 1 неделя | отчёт и roadmap |

## 10. Команда и бюджет ⚠️

- Нужны: продакт / руководитель, разработчик (бэкенд + ML-интеграции), разработчик фронтенда, консультант-врач.
- Бюджет и состав — уточнить; для спринта достаточно прототипа этапа 1 и результатов интервью.
